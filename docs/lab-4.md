# Лаба 4. Веб-клиент

**Цель:** у проекта появляется страница в браузере, которая работает с настоящим API. Подойдёт чистый HTML и JavaScript, подойдёт и фреймворк. Фронтенд можно писать с помощью ИИ, но на приёме спрашивают про связь с сервером: какие запросы уходят, что приходит и как обрабатываются ошибки.

Срок: PR из `lab-4` в `main` до 23:59 накануне встречи 5.

## Что сделать

1. Страница со списком записей из API, формой входа, созданием и удалением.
2. Ошибки API (400, 401, 404) показываются на странице понятным текстом.
3. Если фронтенд и бэкенд на разных портах, на бэкенде настраивается CORS. Если страницу отдаёт сам бэкенд, CORS не нужен, и на приёме нужно объяснить почему.
4. Скриншот интерфейса добавляется в README.

Самый простой вариант без сборки: папка `frontend/` с файлами `index.html` и `app.js`, запуск командой `python -m http.server 5173` из этой папки.

## Чек-лист базы (6 баллов) и как его проверяют

Большая часть пунктов проверяется вручную. Чекер ведёт по сценарию и проверяет то, что видно по HTTP.

| № | Пункт | Как проверяется |
| --- | --- | --- |
| 1 | Страница открывается и загружает список с API, это видно во вкладке Network | Чекер: `frontend_url` отдаёт HTML, через API создаётся запись с меткой `backcheck-XXXX`. Вручную: после обновления страницы метка видна, в Network есть запрос к API |
| 2 | Форма входа: без входа изменять нельзя (кнопок нет или понятная ошибка) | Вручную, в режиме инкогнито |
| 3 | Создание через форму, запись появляется в списке | Вручную: без ручного обновления страницы, в Network виден `POST` с ответом 201 |
| 4 | Удаление через интерфейс | Метка удаляется кнопкой, чекер проверяет, что на сервере её правда нет (`GET` даёт 404) |
| 5 | Ошибки 400, 401, 404 показываются понятным текстом | Вручную: пустое поле, неверный пароль, удалённая запись |
| 6 | CORS настроен, или фронтенд отдаётся самим бэкендом | Чекер отправляет preflight `OPTIONS` с `Origin` фронтенда: нужен 2xx, `Access-Control-Allow-Origin` и разрешённый заголовок `Authorization` |

## Сценарий демонстрации на паре

Открыть страницу, показать вкладку Network, войти, создать запись, получить ошибку на пустом поле, удалить запись, выйти.

## Подсказки

- Запрос из JavaScript: `fetch(url, { method: "POST", headers: { "Content-Type": "application/json", Authorization: ... }, body: JSON.stringify(data) })`.
- `response.ok` равен `false` для ответов 4xx и 5xx. Сам `fetch` выбрасывает исключение, только если сервер вообще не ответил.
- CORS: в FastAPI это `CORSMiddleware`, в Express пакет `cors`, в Go заголовки `Access-Control-Allow-*` и ответ на `OPTIONS`, в Spring `@CrossOrigin` или `CorsConfigurationSource`, в ASP.NET `builder.Services.AddCors`.
- `localhost:5173` и `127.0.0.1:5173` для браузера **разные** origin.
- Если фронтенд генерирует ИИ, ему стоит дать OpenAPI-спецификацию своего API (`/openapi.json`), а потом проверить в Network каждый запрос.
