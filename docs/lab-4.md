# Лаба 4. Веб-клиент

**Цель:** у проекта появляется лицо — страница, которая работает с реальным API. Можно чистый HTML+JS, можно фреймворк. Вайбкодить фронт разрешено, но спрашивать будут про интеграцию: как страница говорит с сервером.

Срок: PR `lab-4 → main` до 23:59 накануне встречи 5.

## Что сделать

1. Страница со списком из API, формой входа, созданием и удалением.
2. Ошибки API (400, 401, 404) показывать человеку текстом на странице.
3. Если фронт и бэк на разных портах — настроить CORS на бэке. Если фронт отдаёт сам бэк — CORS не нужен; объясни почему.
4. Положить скриншот интерфейса в README.

Самый простой вариант без сборки: папка `frontend/` с `index.html` и `app.js`, запуск `python -m http.server 5173` в этой папке.

## Чек-лист базы (6 баллов) и как его проверяют

Большую часть смотрит преподаватель; чекер ведёт его по сценарию и проверяет то, что видно по HTTP.

| № | Пункт | Как проверяется |
| --- | --- | --- |
| 1 | Страница открывается и загружает список с API — видно в Network | Чекер: `frontend_url` отдаёт HTML, и через API создаётся запись-метка `backcheck-XXXX`. Глазами: после обновления страницы метка видна, в Network есть запрос к API |
| 2 | Форма входа: без входа изменять нельзя (кнопок нет или понятная ошибка) | Глазами, в режиме инкогнито |
| 3 | Создание через форму — запись появляется в списке | Глазами: без ручного F5, в Network `POST` с 201 |
| 4 | Удаление через интерфейс | Удаляешь метку кнопкой → чекер проверяет, что на сервере она правда удалена (`GET` → 404) |
| 5 | Ошибки 400, 401, 404 показываются понятным текстом | Глазами: пустое поле, неверный пароль, удалённая запись |
| 6 | CORS настроен или фронт отдаётся самим бэком | Чекер шлёт preflight `OPTIONS` с `Origin` фронта: нужен 2xx, `Access-Control-Allow-Origin` и разрешённый `Authorization`. Объяснить, почему нет ошибки CORS |

## Подсказки

- `fetch(url, { method: "POST", headers: { "Content-Type": "application/json", Authorization: ... }, body: JSON.stringify(data) })`.
- `response.ok` — false для 4xx/5xx; `fetch` сам по себе бросает исключение только если сервер не ответил вообще.
- CORS: FastAPI — `CORSMiddleware`, Express — пакет `cors`, Go — заголовки `Access-Control-Allow-*` и ответ на `OPTIONS`, Spring — `@CrossOrigin` или `CorsConfigurationSource`, ASP.NET — `builder.Services.AddCors`.
- `localhost:5173` и `127.0.0.1:5173` для браузера — **разные** origin.
- Дали ИИ сгенерировать фронт — дай ему OpenAPI-спецификацию своего API (`/openapi.json`), а потом проверь в Network каждый запрос.
