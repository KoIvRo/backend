# Лаба 2. База данных

**Цель:** данные переезжают из памяти в реляционную базу данных и переживают перезапуск сервиса. Появляется вторая сущность своей темы, связанная с главной как «один ко многим». Рекомендуется PostgreSQL, SQLite тоже подходит.

Срок: PR из `lab-2` в `main` до 23:59 накануне встречи 3.

## Что сделать

1. **Поднять PostgreSQL.** Проще всего в Docker:
   ```bash
   docker run -d --name mydb -e POSTGRES_USER=app -e POSTGRES_PASSWORD=app -e POSTGRES_DB=app \
     -p 5432:5432 -v mydb-data:/var/lib/postgresql/data postgres:17-alpine
   ```
   Строка подключения для такой базы: `postgresql://app:app@localhost:5432/app`.
2. **Перенести главную сущность в таблицу.** Строка подключения читается из переменной окружения (например, `DATABASE_URL`). В репозитории лежит `.env.example` с примером, а настоящий `.env` в git не попадает.
3. **Добавить связанную сущность** своей темы с внешним ключом на главную и вложенный маршрут `/api/<главные>/{id}/<связанные>`: создание и список. Например, `POST /api/books/7/loans` и `GET /api/books/7/loans`.
4. **Создавать схему из репозитория**: SQL-скрипт или миграции. Таблицы, созданные руками в консоли, не засчитываются: на другой машине их не будет.
5. **Нарисовать ER-диаграмму** в README. Блок Mermaid `erDiagram` GitHub рисует сам.
6. **Передавать значения в SQL параметрами**, а не склейкой строк.

## ★ (2 балла): миграции, индекс, поиск

Три части. Все три дают 2 балла, две дают 1.

- **Миграции через инструмент и сиды.** Alembic, Prisma, Flyway, goose, EF Migrations, Knex. Сиды это команда, которая заполняет пустую базу тестовыми данными.
- **Индекс под частый запрос.** Индекс создаётся миграцией. В README есть раздел с запросом, командой `EXPLAIN` и её выводом, в котором видно, что база использует индекс (`Index Scan`, `Bitmap Index Scan`). На маленькой таблице PostgreSQL может выбрать полный перебор (`Seq Scan`), поэтому перед `EXPLAIN` в базу добавляется несколько тысяч строк через сиды или `generate_series`.
- **Поиск по тексту.** `GET /api/<items>?q=слово` находит записи, где слово встречается в названии, без учёта регистра. Ищет база: `ILIKE '%слово%'` или полнотекстовый поиск PostgreSQL. Символы `%` и `_` в запросе ничего не ломают.

Пример раздела README:

````markdown
## Индексы

Частый запрос: все выдачи одной книги.

```sql
CREATE INDEX ix_loans_book_id ON loans (book_id);
EXPLAIN SELECT * FROM loans WHERE book_id = 42;
```

```
Bitmap Heap Scan on loans  (cost=4.33..15.82 rows=5 width=48)
  Recheck Cond: (book_id = 42)
  ->  Bitmap Index Scan on ix_loans_book_id  (cost=0.00..4.33 rows=5 width=0)
        Index Cond: (book_id = 42)
```
````

## ★★ (2 балла): правило темы и статистика

- **Правило темы** из [таблицы тем](themes.md): при нарушении сервер отвечает **409 Conflict** и объясняет причину. Например, «все экземпляры на руках» или «время пересекается с другой бронью». Проверка правила и запись выполняются в одной транзакции, чтобы два одновременных запроса не обошли правило. Можно продублировать правило ограничением в самой базе (`UNIQUE`, `CHECK`).
- **Статистика** с агрегатным запросом: `GROUP BY`, `COUNT`, `SUM`, `AVG`. Число считает база данных, а не цикл в коде.

## contract.json: что добавить

```json
{
  "text_field": "title",
  "search": { "param": "q", "field": "title" },
  "child": {
    "resource": "loans",
    "create": { "reader": "Иванов", "taken_at": "2026-10-01" },
    "parent_field": "book_id"
  },
  "rule": {
    "description": "Нельзя выдать книгу, если все экземпляры на руках",
    "parent": { "copies": 1 },
    "setup": [{ "method": "POST", "path": "/api/books/{id}/loans", "body": { "reader": "Иванов", "taken_at": "2026-10-01" } }],
    "violate": { "method": "POST", "path": "/api/books/{id}/loans", "body": { "reader": "Петров", "taken_at": "2026-10-02" } },
    "expect_status": 409
  },
  "stats_path": "/api/books/stats"
}
```

| Поле | Что писать |
| --- | --- |
| `text_field` | Строковое поле главной сущности, в которое чекер запишет строку с SQL-инъекцией |
| `child.resource` | Имя связанного ресурса из пути: для `/api/books/{id}/loans` это `loans` |
| `child.create` | Правильное тело для создания связанной записи |
| `child.parent_field` | Как называется поле связи в ответе, например `book_id` |
| `search` | Только для ★: параметр поиска и поле, в котором ищется слово |
| `rule` | Только для ★★. Чекер создаёт родителя (поля из `parent` подставляются поверх `create`), выполняет запросы из `setup`, потом запрос `violate` и ждёт `expect_status`. `{id}` в пути заменяется на id созданного родителя |
| `stats_path` | Только для ★★: адрес статистики |

Создать родителя, создать связанную запись, показать список связанных, перезапустить сервис, показать, что данные на месте, сохранить строку с инъекцией, удалить родителя и объяснить, что стало со связанными записями.

## Подсказки по стекам

| Язык | Драйвер или ORM | Миграции |
| --- | --- | --- |
| Python | SQLAlchemy 2 и psycopg | Alembic |
| JS/TS | Prisma или pg с Knex | Prisma Migrate, Knex |
| Go | pgx или GORM | goose, golang-migrate |
| Java | Spring Data JPA | Flyway, Liquibase |
| C# | EF Core и Npgsql | EF Migrations |
| PHP | PDO, Eloquent | Laravel migrations, Phinx |

Значения в запрос передаются параметрами, а не склейкой строк: `cur.execute("SELECT * FROM books WHERE id = %s", (book_id,))`, а не `f"... WHERE id = {book_id}"`. Склейка строк и есть путь к SQL-инъекции.

Пять тысяч строк для `EXPLAIN` в PostgreSQL одной командой:

```sql
INSERT INTO loans (book_id, reader, taken_at)
SELECT (random() * 100)::int + 1, 'Читатель ' || n, now() FROM generate_series(1, 5000) AS n;
ANALYZE loans;
```

1. Что такое первичный и внешний ключ? Где они в схеме проекта?
2. Что происходит со связанными записями при удалении родителя? Чем `CASCADE` отличается от `RESTRICT` и `SET NULL`?
3. Что такое SQL-инъекция и почему в этом проекте она не срабатывает?
4. Что такое миграция? Почему таблицы не создают руками в консоли базы?
5. Что такое ORM? Какие у неё плюсы и минусы по сравнению с SQL-запросами вручную?
6. Как устроен индекс и почему с ним поиск быстрее? Какой индекс нужен в этом проекте и под какой запрос?
7. Что показывает `EXPLAIN`? Чем `Seq Scan` отличается от `Index Scan`?
8. Почему индекс нельзя ставить на каждую колонку? Чем он мешает при записи?
9. Что такое транзакция? Что означают буквы ACID? Где транзакция нужна в теме проекта?
10. Что будет, если два запроса одновременно проверят правило темы и оба пройдут? Как это предотвратить?
11. Что такое JOIN? Как одним запросом получить родителя вместе со связанными записями?
12. Что такое проблема N+1 запросов и как её заметить?
13. Чем реляционная база отличается от документной (MongoDB)? Когда документная удобнее?
14. Почему пароль от базы нельзя класть в git? Откуда сервис берёт строку подключения?
15. Как сделан поиск по тексту? Почему для большого каталога ставят отдельную поисковую систему, например Elasticsearch?

Возможные живые правки: добавить колонку через миграцию; добавить фильтр по полю; добавить ограничение `UNIQUE` или `NOT NULL`; добавить в статистику ещё одно число.
