# Лаба 2. Подключаем базу данных

**Цель:** данные живут в реляционной БД, появляется вторая сущность и связь 1:N. Рекомендуем PostgreSQL, SQLite допустим.

Срок: PR `lab-2 → main` до 23:59 накануне встречи 3.

## Что сделать

1. Поднять PostgreSQL. Проще всего в Docker:
   ```bash
   docker run -d --name mydb -e POSTGRES_USER=app -e POSTGRES_PASSWORD=app -e POSTGRES_DB=app \
     -p 5432:5432 -v mydb-data:/var/lib/postgresql/data postgres:17-alpine
   ```
2. Перевести главную сущность из памяти в таблицу. Строку подключения читать из переменной окружения, а в репозиторий положить `.env.example`.
3. Добавить связанную сущность своей темы (1:N) с внешним ключом и вложенный маршрут `/api/<parents>/{id}/<children>`: создание и список.
4. Схему создавать из репозитория: SQL-скрипт или миграции.
5. Нарисовать ER-диаграмму в README (Mermaid `erDiagram` рисуется прямо на GitHub).

## Чек-лист базы (6 баллов) и как его проверяет чекер

| № | Пункт | Как проверяется |
| --- | --- | --- |
| 1 | Создал запись → перезапустил сервис → запись на месте | **Действие:** чекер создаёт запись и просит перезапустить сервис (с `-i`), потом проверяет, что она на месте |
| 2 | Вторая сущность с внешним ключом; вложенный маршрут — создание и список | `POST /api/<parents>/{id}/<children>` → 201 и поле связи = id родителя; ребёнок есть в списке; дети другого родителя туда не попадают |
| 3 | Схема создаётся из репозитория, а не руками в консоли | Чекер ищет миграции и `.sql`; показываешь преподавателю команду, которая создаёт таблицы |
| 4 | Строка подключения из окружения, `.env.example` в репо, пароля в коде нет | `.env.example` есть, `.env` не в git, в файлах нет строк вида `postgres://user:пароль@` |
| 5 | ER-диаграмма в README | Блок `mermaid` с `erDiagram` или картинка; обе сущности, ключи и связь |
| 6 | Строка `'); DROP TABLE <table>;--` сохраняется как обычный текст | Чекер сохраняет её в `text_field`, читает обратно символ в символ, проверяет, что таблица цела |

Чекер ещё создаёт ребёнка у несуществующего родителя (хорошо — 404) и в конце удаляет родителя с детьми. Будь готов объяснить, что стало с детьми и почему.

## ★ (2 балла): миграции, сиды, SQL-фильтры

Три части; все три — 2 балла, две — 1:

- Миграции через инструмент: Alembic, Prisma, Flyway, goose, EF Migrations, Knex.
- Сиды — команда, которая заполняет пустую БД тестовыми данными.
- Фильтрация и сортировка выполняются в SQL (`WHERE`, `ORDER BY`), а не в коде после выборки. Параметр сортировки, например `?sort=title` и `?sort=-title`.

## ★★ (2 балла): фишка темы и статистика

- Фишка из таблицы тем с правильным кодом ошибки — обычно **409 Conflict**: «нельзя занять пересекающееся время», «расход больше остатка».
- Эндпоинт статистики с агрегатным запросом: `GROUP BY`, `COUNT`, `AVG`.

## contract.json: что добавить

```json
{
  "text_field": "title",
  "sort": { "param": "sort", "value": "title", "field": "title" },
  "child": {
    "resource": "checks",
    "create": { "date": "2026-10-01" },
    "parent_field": "habit_id"
  },
  "rule": {
    "description": "Нельзя отметить привычку дважды за один день",
    "setup": [{ "method": "POST", "path": "/api/habits/{id}/checks", "body": { "date": "2026-10-01" } }],
    "violate": { "method": "POST", "path": "/api/habits/{id}/checks", "body": { "date": "2026-10-01" } },
    "expect_status": 409
  },
  "stats_path": "/api/habits/stats"
}
```

`{id}` в `rule` — id родителя, которого чекер создаст сам. `sort`, `rule`, `stats_path` нужны только для звёздочек.

## Сценарий демонстрации на паре

Создать родителя → создать ребёнка → список детей → перезапуск → данные на месте → строка-инъекция → удалить родителя и объяснить, что стало с детьми.

## Подсказки по стекам

| Язык | Драйвер / ORM | Миграции |
| --- | --- | --- |
| Python | SQLAlchemy 2 + psycopg | Alembic |
| JS/TS | Prisma или pg + Knex | Prisma Migrate, Knex |
| Go | pgx или GORM | goose, golang-migrate |
| Java | Spring Data JPA | Flyway, Liquibase |
| C# | EF Core + Npgsql | EF Migrations |
| PHP | PDO, Eloquent | Laravel migrations, Phinx |

Параметризованный запрос, а не склейка строк: `cur.execute("SELECT * FROM items WHERE id = %s", (item_id,))`, а не `f"... WHERE id = {item_id}"`.
