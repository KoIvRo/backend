# Темы проектов

Тема выбирается на первой встрече через колесо. У всех тем одинаковое устройство:

- **главная сущность**: с ней работает лаба 1 (создать, получить, изменить, удалить);
- **связанная сущность**: появляется в лабе 2. У одной главной записи может быть много связанных, это связь «один ко многим» (1:N). Например, у одной книги много выдач;
- **фишка**: бизнес-правило темы, которое нужно для ★★ в лабе 2. Когда правило нарушают, сервер отвечает **409 Conflict** и объясняет, что не так;
- **статистика**: идея для эндпоинта со статистикой, тоже для ★★ в лабе 2. Её считает база данных через `COUNT`, `SUM`, `AVG` и `GROUP BY`.

Поэтому чек-листы у всех одинаковые, а проекты разные.

Правила колеса:

1. Выпавшая тема убирается из колеса, двух одинаковых тем в группе нет.
2. У каждого есть один реролл: можно крутить ещё раз, но тогда остаётся вторая тема.
3. Темами можно поменяться, если согласны оба.
4. Можно предложить свою тему, если в ней есть главная сущность, связанная сущность 1:N и понятное правило для 409. Свою тему нужно согласовать до встречи 2.

## Как читать строку таблицы на примере

Тема 20, «Библиотека».

- Главная сущность **Книга**: название, автор, год, сколько экземпляров в библиотеке. В лабе 1 это `/api/books`.
- Связанная сущность **Выдача**: кому выдали, когда, вернули или нет. У одной книги много выдач. В лабе 2 это `/api/books/{id}/loans`.
- Фишка: если все экземпляры уже выданы, `POST /api/books/7/loans` отвечает `409 Conflict` и `{"error": "все экземпляры на руках"}`.
- Статистика: `GET /api/books/stats` возвращает, сколько раз выдавали каждую книгу. Число считает база данных, а не цикл в коде.
