# Лаба 1. Первый сервис: HTTP CRUD в памяти

**Цель:** написать HTTP-сервис, который отвечает по правилам REST. Главная сущность твоей темы, данные хранятся в памяти (список или словарь). Любой язык и фреймворк.

Срок: PR `lab-1 → main` до 23:59 накануне встречи 2.

## Что сделать

1. Сервис на порту 8000 с эндпоинтами `GET /health` и CRUD главной сущности по пути `/api/<сущности во множественном числе>`: например, `/api/habits`, `/api/rooms`, `/api/cats`.
2. Заполнить `README.md`: тема, как запустить, таблица эндпоинтов.
3. Заполнить `requests.http` всеми запросами — по нему идёт демонстрация.
4. Заполнить `contract.json` под свою тему — по нему работает чекер.

## Чек-лист базы (6 баллов) и как его проверяет чекер

| № | Пункт | Как проверяется |
| --- | --- | --- |
| 1 | README (тема, как запустить, таблица эндпоинтов) и `requests.http` со всеми запросами | Чекер находит файлы и таблицу с путём ресурса; «как запустить» смотрит преподаватель |
| 2 | `GET /health` → 200 и `{"status":"ok"}` | 200, `Content-Type: application/json`, `"status": "ok"` |
| 3 | `POST /api/<items>` → 201 и объект с `id` | Тело из `contract.create` → 201, есть `id`, все отправленные поля вернулись с теми же значениями |
| 4 | `GET /api/<items>` и `GET /api/<items>/{id}` работают; неизвестный id → 404 | В списке есть созданная запись, по id та же запись, `missing_id` → 404 |
| 5 | `PUT` или `PATCH` обновляет; `DELETE` → 204; после удаления `GET` → 404 | PATCH (или PUT, если PATCH нет) → GET видит изменение → DELETE ровно 204 → GET 404 |
| 6 | Сломанный JSON или пустое обязательное поле → 400, а не 500 и не падение | Битый JSON, пустое и отсутствующее `required_field` → 400 (422 тоже засчитывается); сервер после этого жив |

## ★ (2 балла): валидация и пагинация

- Валидация **всех** полей, ошибки в одном формате: `{"error": "текст", "field": "имя поля"}` и код **400**.
- Фильтр и пагинация списка: `?limit=10&offset=0&<поле>=<значение>`.

Чекер: каждый случай из `contract.errors` (нужен хотя бы один на каждое поле из `create`) → 400 и правильное `field`; фильтр возвращает только подходящие записи; `limit=2&offset=0` и `limit=2&offset=2` — две разные страницы.

## ★★ (2 балла): документация и логи

- OpenAPI/Swagger по адресу `/docs`.
- Лог каждого запроса: метод, путь, статус, время ответа в мс. Например: `GET /api/habits/7 404 1.3ms`.

Чекер: `/docs` отдаёт HTML, OpenAPI-спецификация находится и содержит пути ресурса; для лога чекер шлёт запрос с меткой `backcheck-log-XXXX` — покажи эту строку в терминале сервиса.

## contract.json для лабы 1

```json
{
  "base_url": "http://localhost:8000",
  "resource": "habits",
  "id_field": "id",
  "missing_id": "999999",
  "list_key": null,
  "create": { "title": "Пить воду", "goal_per_day": 8, "status": "active" },
  "update": { "title": "Пить много воды" },
  "required_field": "title",
  "errors": [
    { "body": { "title": "" }, "field": "title" },
    { "body": { "goal_per_day": -1 }, "field": "goal_per_day" },
    { "body": { "status": "unknown" }, "field": "status" }
  ],
  "filter": { "param": "status", "value": "active", "other": "archived" }
}
```

`errors` и `filter` нужны только для ★. Если список отдаётся как `{"items": [...]}`, поставь `"list_key": "items"`.

## Сценарий демонстрации на паре

health → создать → список → получить → обновить → удалить → получить (404) → создать со сломанным JSON (400).

## С чего начать на своём языке

| Язык | Минимум | Подсказка |
| --- | --- | --- |
| Python | FastAPI + uvicorn | `@app.post("/api/items", status_code=201)`; 422 → 400 через свой `exception_handler(RequestValidationError)` |
| JS/TS | Express | `app.use(express.json())`; ошибку разбора JSON ловит middleware с четырьмя аргументами `(err, req, res, next)` |
| Go | `net/http` (Go 1.22+) | `mux.HandleFunc("GET /api/items/{id}", ...)`, `r.PathValue("id")` |
| Java | Spring Boot (Web) | `@RestController`, `ResponseEntity.status(201)`; `@ControllerAdvice` для 400 |
| C# | ASP.NET Core Minimal API | `app.MapPost(...)`, `Results.Created(...)`, `Results.NoContent()` |
| PHP | Slim или Laravel | `$response->withStatus(201)` |

## Вопросы, которые могут задать на приёме

1. Что происходит по шагам, когда вводишь адрес в браузере?
2. Чем PUT отличается от PATCH, а POST от PUT?
3. Что такое идемпотентность? Какие методы идемпотентны?
4. Почему создание возвращает 201, а удаление 204?
5. Чем 400 отличается от 404 и от 500? Кто «виноват» в каждом случае?
6. Что такое порт и почему сервис слушает, например, 8000?
7. Что будет с данными после перезапуска и почему?
8. Зачем заголовок `Content-Type`?
9. Покажи, где в коде проверяется обязательное поле.
10. Почему в REST URL — существительное во множественном числе, а не `/createItem`?

Возможные живые правки: добавить поле в сущность; поменять код ответа; добавить `GET /api/<items>/count`.
